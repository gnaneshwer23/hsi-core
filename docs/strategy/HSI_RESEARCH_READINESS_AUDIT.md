5 November 2026. This maps the supplied product/discovery, RAG/GraphRAG and trust/operations recommendations to the repository. It is an implementation audit and build plan, not independent validation of the external articles or a claim that every item described as “missing” is absent.

## Decision

Keep **Human Super Intelligence** focused on a repeated translational immunology investigation: question → inspectable source evidence and context → competing explanations → independent review → reproducible research brief.

RA/anti-TNF remains the first scientific proof programme. The current saved workbench uses a bounded SSc planner/source context; it is an engineering surface, not proof that an RA workflow or a 20-condition scientific product has passed live acceptance. The 20-condition validation lab tests software behavior only.

Retain the current Vite/React, Bun and PostgreSQL architecture. Hybrid lexical/vector/graph retrieval is a component within it. The notes' Next.js/FastAPI/Neo4j/Qdrant stack is an option list, not an instruction to rewrite HSI or proof of a necessary dependency.

## Changes in this increment

- The research-readiness module validates a 50-question design bank and generates deterministic bank/case/prompt bindings, pending annotation slots, a non-activating report and current method registry.
- The readiness CLI prepares/checks those local artifacts. No provider, outreach or database operation occurs.
- The evaluation/research-readiness directory contains the questions, two empty SME packets, registry, readiness and annotation protocol.
- The fixture adapter/builder/browser now preserve and verify record-level lineage. A dictionary lists every actual source field, presence count and type.
- Discovery, retrieval and operating documents distinguish proposed scope from measured/live capability.

## Next build sequence

1. **Source and expert readiness:** clear rights and scientific context for a bounded RA corpus; bind a permitted source packet and two independent expert annotations to each selected question. Complete the paused live auth/source/role acceptance on approved staging. Do not use synthetic cards as scientific labels.
2. **Measured retrieval baseline:** implement exact/lexical retrieval plus bounded typed graph traversal and auditable channel receipts; retain metadata filters and permissions before ranking and on later reads. Measure recall and relevant opposing evidence against frozen expert labels.
3. **Hybrid comparison:** add a versioned semantic channel only with approved embedding/data terms, budget and operating ownership. Compare text-only, graph-only and fused retrieval on the same held-out cases. Do not assert hybrid superiority from architectural diagrams.
4. **Bounded synthesis:** activate a candidate only after source/claim-context verification, contradiction handling, latency/cost and safety acceptance. Keep confidence uncalibrated until a validated calibration method exists.
5. **Real-team pilot:** run the scoped design-partner workflow, paired task measurements and retention/usefulness observation after data/operational gates. Complete restore/rollback, security and support ownership acceptance.

This does not restart Delivery A–H or mark their live/scientific gates complete.

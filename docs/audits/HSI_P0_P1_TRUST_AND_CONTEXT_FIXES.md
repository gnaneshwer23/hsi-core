## Compatibility and activation

The transport is deliberately unwired. Provider-specific request/auth encoding is a trusted server dependency, and actual response codecs, provider request IDs, cost/token limits, retries/idempotency and approved data handling still need integration. No generic injected callback is treated as a verified live provider. Direct transport use must remain behind `createProviderRunner` so deadlines and response bounds apply. Production egress/firewall/DNS/TLS/proxy behavior needs deployment acceptance with controlled fault tests; offline pinning tests do not substitute for it. Conservative address rules may deny some legitimate special-purpose ranges; do not weaken them based on an untrusted request.

Comparison version/IDs change intentionally. Existing immutable comparison records retain their old version; reruns must produce new records rather than rewrite historical ones. Five coarse context axes and method notes do not implement the full passage-linked dose/time/assay/cohort/estimand schema or scientifically validated conflict classification. Both-sided missing axes are explicitly reported but still require scientific review. No approval or graph promotion is granted.

Outcome attachments now require an independently implemented backend authority; no authority is provisioned or inferred from a caller's IDs. The current saved-outcome service still supplies no optional attachments. Do not wire request bodies directly to the compiler's options/authority. Stored attachments must be independently resolved, source-cleared, authorized and hashed by the backend. Brief acceptance does not transfer to graph approval.

## 2. Additional code errors reproduced and repaired

Nine regression tests failed before the fixes. The follow-up addresses:

- **Validation/transmission mismatch:** provider configuration and request properties could change between validation and the later object copy. Read known fields once, then validate and use that snapshot.
- **Unsupported negative verdicts:** model `contradicts` outputs could count without an exact nonblank source span. Both positive and negative scientific assertions now require a valid span; otherwise the verdict is insufficient evidence.
- **Malformed model output accepted:** a missing/non-string/blank rationale or invalid verdict could be salvaged into an assessment. Validate the response schema; the dual-model harness records invalid output as technical abstention, separately from scientific insufficiency.
- **Verdict bound to a mutated claim:** a callback could change the original claim ID while execution awaited a response. Snapshot submitted inputs and returned model responses so validation, evaluation and returned identity describe the same values.
- **Direct entry-point gap:** direct dual challenge execution could call runners despite failed grounding checks; direct adjudication trusted the disposition label alone. Use one shared full-receipt check across passage, harness, dual-challenge and adjudication boundaries. These low-level injected-runner helpers are not independently authorized production egress APIs; the server's source-clearance boundary is still required.
- **Causal gate normalization:** casing/whitespace could evade the existing causal/therapeutic predicate list. Normalize those values consistently before exception handling. This is a deterministic guard, not semantic detection of every causal paraphrase.
- **False comparability:** matching disease/context could produce consistency or potential conflict between different subject/object claims. Require aligned entities and predicates before classification. Shared disease alone is insufficient. Comparator version is now `0.1.1`; old saved artifacts are not silently rewritten.

This does not finish experimental-context extraction, scientific conflict adjudication, opposing-search completeness, the immunology benchmark or the complete live research journey. Model agreement and exact spans remain necessary engineering evidence, not scientific truth.

### Material corrections to the proposal

1. **Incorrect academic attribution.** [arXiv:2408.13378](https://arxiv.org/abs/2408.13378) is the DrugAgent paper. It does not substantiate BioGraphRAG, the dynamic-KG repository, a six-week HSI schedule or production readiness. Medical-Graph-RAG identifies [its own paper, 2408.04187](https://arxiv.org/abs/2408.04187). Use a project's actual paper/code for each claim rather than attach one citation to unrelated recommendations.
2. **BioGraphRAG API is not a finished service.** Its inspected FastAPI `/qa` endpoint returns a TODO response. Retrieval/pruning code exists, but the recommendation must distinguish that code from completed API integration.
3. **README claims are not validation.** Phrases about verified biology, governed answers and reliable evidence must be treated as project claims until independently evaluated. A citation matching a retrieved identifier does not prove passage entailment or mechanism correctness.
4. **License badges are insufficient evidence for copying.** The dynamic-KG README advertises MIT, but no license/notice file was found in its inspected tree and GitHub metadata reports no license. Record the ambiguity rather than describe it as cleared for reuse. CLADD illustrates the inverse: metadata is `NOASSERTION`, while its actual LICENSE explicitly identifies Apache-2.0. Inspect files, dependencies and data/model terms separately.
5. **Code license does not clear scientific sources.** These repositories do not supply HSI's passage rights, retraction clearance, researcher isolation, scientific reviewer authority or immunology-wide gold data. Medical-Graph-RAG's clinical/data framing is particularly incompatible with importing material into this research-only repository without separate governance. Its README's account of web searches is not an HSI rights policy.
6. **No verified six-week production promise.** Replace the calendar claim with dependency gates: tested boundary fixes; approved source/provider adapters; real staging isolation and reviewer acceptance; a connected context-conflict audit; independently adjudicated 120-case evaluation; operational release evidence. Human scientific and source-policy dependencies cannot be solved by importing frameworks.
7. **Graph UI choices need a measured need.** Existing HSI graph/workbench views remain the starting point. React Flow, Cytoscape or Sigma can be evaluated for a specific interaction/performance gap; a new renderer is not a prerequisite for scientific reliability.

## 4. Practical reuse decision

Current decision: **no new runtime dependencies or stack migration**. BioGraphRAG's bounded retrieval/pruning, VeritasGraph's answerability/receipt patterns and DrugAgent's explicit separation of evidence channels are candidates for small isolated experiments, not blanket platform adoptions. The dynamic-KG implementation may inform design review, but code-copying needs the licensing ambiguity resolved first. Medical-diagnosis, clinical-data and drug-prediction workflows are outside HSI's initial research release.

For any proposed import, require: a pinned commit and exact module; a concrete HSI gap; inspected code/dependency/data terms; an adapter that preserves source/context/provenance and human review; comparison against the current deterministic baseline under equal evidence/cost conditions; documented scientific failure cases; and an operational rollback path. Reject imports that add complexity without measured benefit.

The existing draft remains a review vehicle. Passing code checks does not authorize merging it, applying held migrations, enabling writes, approving sources or promoting scientific claims.

# SME-02B — Neon schema candidate
Status: offline candidate; not applied or tested against Neon. SQL is outside db/migrations intentionally. No changes to migration holds. Depends on independent SME-01A acceptance and ADR-012/013/014 owner decisions.
## Design
Composite tenant/scope/record keys prevent cross-scope version/grant references. Deferred current-version FK requires atomic creation. Audit events contain no body or source text; retention and pseudonymisation policy must be approved before use. All four tables FORCE RLS with no allow policies. No runtime grants. No external dependencies. Data classification constraints are not PHI detection; ingestion must reject sensitive content independently.
## Restricted procedure contract (not implemented)
Use dedicated non-login function owner, fixed search_path, qualified relations, no PUBLIC execute, no direct runtime table grants. Verify Neon session inside transaction using reviewed ADR-013 pattern; resolve active canonical tenant/scope membership (ADR-014); reject forged GUCs, revoked sessions and grants. Do not create parallel membership registry. Read only active unexpired records and explicit owner/grantee access. Lock record for revise/revoke/delete, enforce expected version and idempotency, audit atomically. Recheck authorization at response delivery; invalidate derived indexes. Delete versions/grants and derived copies under approved retention policy; audit minimisation and backup expiry required. No graph or training writes.
